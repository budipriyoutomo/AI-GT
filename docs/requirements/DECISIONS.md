# Decisions

This log records only decisions with material product or engineering consequences. “Inferred” means code supports the conclusion but no explicit rationale was found.

## DEC-001 — Templates are immutable visual anchors

**Status:** Active
**Date:** Unknown
**Area:** Product / Architecture

### Decision
AI and backend may generate copy, typography suggestions, and optional thematic imagery, but must not mutate `template_config`, layout, background, or authored visual scheme.

### Context
AI-GT promises fast, professional content without allowing generated output to destroy template composition.

### Rationale
Documented as **Template Integrity**.

### Impact
Template JSON is read-only at runtime; template authors control visual geometry. AI receives a compiled copy brief instead of raw template JSON.

### Evidence
`AGENTS.md` §6; `docs/PRD-AI-GT-v2-synced.md` §4.2–4.3; `backend/app/services/generate_service.py`; `backend/scripts/seed_template_data/README.md`.

## DEC-002 — Resolve branding and copy once in TypeScript for two renderers

**Status:** Active
**Date:** Unknown
**Area:** Architecture / UX

### Decision
`frontend/src/lib/template/resolve.ts` is the pure, single resolver for brand colors/fonts/logo/tagline and generated/editor copy. CSS preview and Fabric canvas only render its resolved output.

### Context
Separate brand and copy paths caused preview/editor/export mismatch risk.

### Rationale
Export is generated by Fabric in the browser; moving resolution to backend would create another implementation and would not address client toggle state.

### Impact
New template features require parity in both renderers, but must not create a second brand-adaptation path. `brand_applied` stores user intent, not a brand snapshot.

### Evidence
`AGENTS.md` §6; `docs/handoff-improvements/handoff8a.md`; `frontend/src/lib/template/resolve.ts`; `frontend/src/lib/editor/preview-config.ts`; renderer-parity tests.

## DEC-003 — Branded mode applies the entire company profile

**Status:** Active
**Date:** Unknown
**Area:** UX / Data

### Decision
The `branded`/`brand_applied` choice applies all profile-derived data together: color, font, logo, tagline, and footer contacts. Unbranded mode uses `DEFAULT_COMPANY_PROFILE` rather than a mixture of user and generic data.

### Context
Mixed branding produces inconsistent gallery, editor, and export output.

### Rationale
Documented as a renderer-consistency rule.

### Impact
Gallery browsing starts generic; users opt in to brand preview. Existing projects without `brand_applied` render unbranded for backward compatibility.

### Evidence
`AGENTS.md` §6; `docs/PRD-AI-GT-v2-synced.md` §4.2; `frontend/src/lib/{defaults.ts,template/resolve.ts}`.

## DEC-004 — Address is not contact JSON; render it through one adapter

**Status:** Active
**Date:** Unknown
**Area:** Data / Architecture

### Decision
Business address remains a separate `company_profiles.address` field and maps to a footer `location` slot only through `buildFooterContact()` before resolution.

### Context
Both renderers consume footer contact slots; duplicating mapping or storing `location` in contact would cause persistence/render divergence.

### Rationale
Documented explicitly.

### Impact
Settings must not inject address into `contact`; callers prepare footer contact before invoking the resolver.

### Evidence
`AGENTS.md` §6; `docs/TECHNICAL_DOCUMENTATION.md` §§5, 12; `frontend/src/lib/template/footer-contact.ts`; migration `0010_add_address_to_company_profiles.py`.

## DEC-005 — AI copy is mandatory; AI imagery is best-effort and parallel

**Status:** Active
**Date:** Unknown
**Area:** Architecture / Reliability

### Decision
Copy and optional image generation run concurrently through `ai_service`. Copy has a 30-second timeout and invalid-JSON retries; image has a 60-second timeout and failures return no image rather than fail the session.

### Context
Copy is the primary usable output; image is an enhancement.

### Rationale
Documented as required provider-failure behavior.

### Impact
Generation sessions fail on copy failure but can complete image-less. Providers/models are configured from environment.

### Evidence
`AGENTS.md` §5; `docs/TECHNICAL_DOCUMENTATION.md` §§8–9; `backend/app/services/ai_service.py`.

## DEC-006 — Asset records use CDN-resolved relative paths; logo keys are deterministic

**Status:** Active
**Date:** Unknown
**Area:** Data / Infrastructure

### Decision
Persist R2 asset paths rather than absolute CDN URLs. Logos normalize to PNG and overwrite `permanent/logos/{user_id}/logo.png`; their persisted path carries a `?v=` cache-busting query.

### Context
Avoid embedding a CDN host in data, prevent logo-object orphaning, and avoid stale CDN logo caching.

### Rationale
Documented in the logo-upload handoff and technical documentation.

### Impact
`resolveAssetUrl()` adds the CDN base at display time. Logo deletion clears the DB value but does not delete the one deterministic R2 object.

### Evidence
`docs/TECHNICAL_DOCUMENTATION.md` §10; `docs/handoff-improvements/upload-company-logo.md`; `backend/app/services/storage_service.py`; `frontend/src/lib/assetUrl.ts`.

## DEC-007 — Generation state is persisted, with background execution and one-hour expiry

**Status:** Active
**Date:** Unknown
**Area:** Architecture / Data

### Decision
Generate requests create database-backed sessions; FastAPI background tasks process them, and a 30-minute scheduler removes expired temporary assets for one-hour sessions.

### Context
The backend must remain stateless and generation can outlive an HTTP response.

### Rationale
Documented as a core architectural principle.

### Impact
Frontend polls session status. `GenerateSession`, variants, and projects are the lifecycle record.

### Evidence
`AGENTS.md` §§5, 7; `backend/app/main.py`; `backend/app/services/{generate_service.py,cleanup_service.py}`.

## DEC-008 — Current supported generation is Quick Generate; Campaign is premium-gated

**Status:** Requires Confirmation
**Date:** Unknown
**Area:** Product / Scope

### Decision
Code currently rejects every non-null `campaign_data` as `FEATURE_REQUIRES_PREMIUM`, while automatically selecting the quick result into a project.

### Context
The synced PRD presents a unified four-step flow with carousel story-flow as current MVP behavior. Create UI exposes carousel inputs and sends `campaign_data`, which the backend rejects.

### Rationale
Rationale for the gate is documented in technical docs/`FlowGenerate.md`; the product decision to show currently blocked carousel UI is not explicitly documented.

### Impact
Carousel/campaign must not be represented as end-to-end available until PRD, UI, entitlement model, and service behavior agree.

### Evidence
`backend/app/services/generate_service.py`; `backend/app/schemas/generate.py`; `frontend/src/app/create/page.tsx`; `docs/PRD-AI-GT-v2-synced.md`; `docs/TECHNICAL_DOCUMENTATION.md`; `FlowGenerate.md`.

## DEC-009 — Company profile refreshes once per Create-page mount

**Status:** Active
**Date:** Unknown
**Area:** UX / Architecture

### Decision
`/create` invokes shared `refreshProfile()` on mount; the context guards overlapping refreshes and retains cached profile data if refresh fails.

### Context
A profile edited in Settings should affect new work without requiring logout/login, but steps of one wizard should use one profile snapshot.

### Rationale
Documented in Handoff 2.

### Impact
New projects use recent profile data; existing project behavior remains live-resolved in editor, which is a separate product policy to confirm.

### Evidence
`docs/handoff-improvements/merge-in-create.md`; `frontend/src/app/create/page.tsx`; `frontend/src/lib/auth.tsx`.

## DEC-010 — Template Lab is embedded, file-first, and explicitly future scope

**Status:** Proposed
**Date:** Unknown
**Area:** Infrastructure / Internal tooling

### Decision
Template Lab would live inside AI-GT behind an environment flag, reuse the production renderer, keep drafts separate from live templates, and seed via committed JSON files rather than a parallel direct-DB path.

### Context
Manual JSON editing lacks immediate visual feedback and risks renderer drift.

### Rationale
Documented in the Template Lab MVP spec.

### Impact
Do not build/administer it as if currently available. WYSIWYG drag/resize is Phase 2 and out of its MVP.

### Evidence
`docs/template_lab_spec.md`.

## DEC-011 — Foreground thumbnails and full-bleed backgrounds are separate assets

**Status:** Active
**Date:** 2026-07-02
**Area:** Product / Data / Architecture

### Decision
`thumbnail_url` is the foreground/gallery asset; `background_url` is the separate full-bleed background asset for templates whose config declares `source: "background"`. Legacy image-background rows may be backfilled once, without overwriting admin-uploaded values.

### Context
A single image field could not distinguish a gallery/foreground image from a template background.

### Rationale
Explicitly documented in the seed authoring rules and migration/seed backfill code.

### Impact
Both CSS and Fabric renderers and project snapshots must carry the same asset selection. Current editor/export code does not yet propagate `background_url` equivalently, so the decision is not fully realized in all surfaces.

### Evidence
`backend/scripts/seed_template_data/README.md` §§2–3, 7; `backend/scripts/seed_templates.py`; migration `0007_add_background_url_to_templates.py`; `frontend/src/components/template/TemplateRenderer.tsx`; `frontend/src/lib/editor/canvas-spec.ts`.

## DEC-012 — Alembic history is linearized, but legacy reconciliation remains pinned to 0006

**Status:** Requires Confirmation
**Date:** Unknown
**Area:** Data / Infrastructure

### Decision
The executable migration chain currently runs from `0001` through `0010`, with later idempotent guards for drifted environments. The separate reconcile script/SQL still stamps `alembic_version` to `0006`.

### Context
The repository documents historical duplicate revision IDs and a one-time schema reconciliation path.

### Rationale
The linearized chain and drift guards are explicit; the continued `0006` target is not explained or reconciled with the current head.

### Impact
Running `make reconcile` on a current existing database can leave `projects.thumbnail_url`, `background_url`, `copy_intent`, and `address` outside the stamped migration state. The intended safe procedure for legacy databases requires human confirmation.

### Evidence
`backend/alembic/versions/0001_initial_schema.py` through `0010_add_address_to_company_profiles.py`; `backend/scripts/reconcile_schema.py`; `backend/scripts/reconcile_schema.sql`; `README.md`.

## DEC-013 — Template seeding behavior is contradictory across docs and code

**Status:** Requires Confirmation
**Date:** Unknown
**Area:** Data / Infrastructure

### Decision
`README.md` and the Makefile describe `make seed` as resetting the `templates` table, while `backend/scripts/seed_templates.py` implements a name-based, non-destructive upsert that preserves unrelated rows and non-empty admin asset URLs.

### Context
Seeding is intended to be reproducible while admin-managed image fields should not be overwritten by empty JSON values.

### Rationale
Rationale for the conflicting descriptions is not explicitly documented.

### Impact
Operators may expect destructive reset semantics when the script is actually additive/update-oriented. This affects production safety, rollback assumptions, and Template Lab’s proposed file-first workflow.

### Evidence
`README.md`; `Makefile`; `backend/scripts/seed_templates.py`; `docs/template_lab_spec.md`.
